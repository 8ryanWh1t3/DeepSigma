# Liddell Lens version 1 contract

User-facing brand is DEEP SIGMA Liddell Lens. Functional description is a decision loss meter comparing baseline and CERPA. The name is an original Deep Sigma adaptation inspired by B. H. Liddell Hart; no endorsement or validated military decision model is implied.

Input object has exactly schema_version ('1.0'), data_kind ('illustrative' or 'observed'), title (nonempty string), cases (nonempty array, maximum 10000). A case has exactly case_id (nonempty unique string), baseline, cerpa. Strings have maximum length 200 and must already be trimmed.

Each run has exactly elapsed_minutes, effort_minutes, clarification_cycles, unresolved_contradictions, closed, supported, authorized. elapsed_minutes is a finite number in [0, 1000000000]; effort_minutes has exactly preparation, execution, review, clarification, rework (each finite numeric [0,1000000000]). Boolean values are not numbers. Counts are integers in [0,1000000]. closed, supported, authorized are strict booleans. Extra keys are rejected at every level to catch typos. Missing values are errors; never silently default to zero. Report errors with a field path.

Effort values are nonoverlapping person-minutes summed across people. elapsed_minutes is wall-clock minutes from intake to closure, or to the observation cutoff when not closed. Effort and elapsed are different dimensions. A run qualifies for completed decision timing iff closed AND supported AND authorized. These flags are recorded human assessments, not independently validated judgments. Unresolved contradictions are reported separately, not automatically reinterpreted as failed decisions.

JavaScript UMD engine js/engine.js exposes global LiddellLens and CommonJS exports. API validate(data) throws Error on invalid input; analyze(data) returns below. Python python/liddell_lens.py exposes validate(data) raising ValueError, analyze(data), CLI input.json --output result.json and optional --csv case_results.csv. Both engines validate first and do not mutate input. No rounding in engine results, only presentation. Input unknown keys and dangerous prototype names are rejected as unknown fields. Floats at/below limits reduce overflow risk; tests compare floats with tolerance.

Result exact keys:
- schema_version: '1.0'
- data_kind, title, case_count
- arms: baseline and cerpa; each {case_count, completed_supported_authorized, completion_rate_pct, total_effort_minutes, effort_minutes: {preparation,execution,review,clarification,rework}, clarification_cycles, unresolved_contradictions}
- comparison: total_effort_minutes, rework_minutes, clarification_cycles, unresolved_contradictions. Each is {baseline,cerpa,saved,percent_saved}. saved = baseline - cerpa. percent_saved = null if baseline == 0, else saved / baseline * 100. Negative savings means CERPA used more or had more unresolved items.
- If a computed percentage is nonfinite (possible for extremely tiny positive baselines), analyze raises an error containing 'percentage exceeds finite range'. Never serialize Infinity or silently turn it into null.
- paired_elapsed: {case_count,excluded_case_ids,baseline_mean_minutes,cerpa_mean_minutes,saved_mean_minutes,percent_saved}. Use only cases qualifying in BOTH arms. Means and percent null when no eligible pair. percent null if baseline mean is zero. Explicitly retain excluded IDs and all cases in other metrics.
- case_results: ordered array of {case_id,baseline_complete,cerpa_complete,baseline_effort_minutes,cerpa_effort_minutes,effort_saved_minutes,baseline_elapsed_minutes,cerpa_elapsed_minutes,elapsed_saved_minutes}. elapsed_saved_minutes is null unless both qualify; other elapsed fields retain raw values for transparency.
- warnings: ordered array. First always 'Recorded support and authority flags are human assessments; this tool does not verify evidence or authorization.' If illustrative add 'ILLUSTRATIVE DATA: these results are examples, not measured Deep Sigma performance.' Next if exclusions exist add 'Elapsed-time comparison excludes cases without a closed, supported, authorized decision in both arms; inspect completion counts and excluded cases.' Last always 'Observed differences do not establish causation. Use comparable cases and include all preparation, review, and collection costs in the evaluation.'

Dashboard: offline index.html loaded via file URL, classic local scripts (no fetch, imports, CDNs, network, analytics, or storage); default example must say illustrative prominently. Import local JSON via file input, report field errors, render text via textContent, export results JSON and per-case CSV, toggle built-in examples showing benefit and overhead exceeding benefit. Never label total preparation/review as waste or invent a single efficiency score. No AC-versus-DC or physics claims in app. Show time to complete ONLY for paired-complete cases, success counts for all cases. Display negative savings plainly. An imported invalid file must clear stale displayed results and disable export. Null percentages must display N/A (zero baseline or no eligible pairs), not 0%.

Palette: white #FFFFFF, dusky green #004F46, muted sage #B7C2A9, pistachio #648F7B. Use white dominant, deep-green text; avoid red/blue/yellow. Readability first. Do not silently save user data. Responsive accessible controls and table labels.
